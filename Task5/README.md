# Task 5. Проектирование GraphQL API

## 1. Цель задания

Сервис `client-info` хранит объёмную карточку клиента, потенциально до 500 атрибутов. Разные потребители и пользовательские сценарии требуют разные наборы полей.

Исходный REST API предоставляет отдельные ресурсы:

- `GET /clients/{id}`;
- `GET /clients/{id}/documents`;
- `GET /clients/{id}/relatives`.

Это приводит к нескольким запросам для одной страницы. Возвращать все 500 атрибутов одним REST-ответом тоже невыгодно, потому что возникает over-fetching, то есть передача данных, которые потребителю не нужны.

Нужно создать эквивалентную GraphQL-схему, которая покрывает операции исходного Swagger и позволяет клиенту выбирать поля.

## 2. Файлы решения

| Файл              | Назначение                                                                      |
|-------------------|---------------------------------------------------------------------------------|
| `schema.graphql`  | GraphQL SDL, описание типов и корневого query.                                  |
| `queries.graphql` | Примеры запросов, эквивалентных REST-операциям, и объединённый запрос карточки. |
